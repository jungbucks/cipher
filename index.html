암호의 세계

암호화와 복호화가 어떻게 일어나는지, 눈으로 직접 확인해보세요.

치환형 암호
시저 암호 (Caesar Cipher)
알파벳을 일정한 수만큼 밀어서 다른 글자로 바꾸는 가장 오래된 암호입니다. 로마의 율리우스 카이사르가 군사 통신에 사용했다고 전해집니다.
알파벳 휠 — 아래 슬라이더를 움직이면 안쪽 고리가 돌아가요
평문 입력
⚠️ 영문 알파벳만 암호화돼요 — 한글·숫자·기호는 자동으로 빠집니다

전치형 암호
레일 펜스 암호 (Rail Fence Cipher)
글자를 지그재그(W자) 모양으로 여러 줄(레일)에 써넣은 뒤, 줄 순서대로 읽어내는 전치형 암호입니다. 글자의 순서가 바뀔 뿐 글자 자체는 변하지 않습니다.

대칭 키 암호화
Symmetric Key Encryption
암호화와 복호화에 같은 키를 사용하는 방식. 빠르고 효율적이지만 키를 어떻게 안전하게 공유할지가 가장 큰 과제입니다.
작동 원리

특징
⚡
빠른 속도
공개 키 방식 대비 100~1000배 빠름. 대용량 데이터 암호화에 적합
📦
단순한 구조
키 하나로 암복호화 모두 처리. 구현이 상대적으로 단순하고 하드웨어 최적화 용이
🔑
키 배포 문제
사전에 안전한 채널로 키를 공유해야 함. 첫 번째 공유 자체가 보안 취약점
📊
키 수 폭발적 증가
n명 통신 시 n(n-1)/2개 키 필요. 10명 → 45개, 100명 → 4,950개
대표 알고리즘
AES-128/256 ChaCha20 DES (구식) 3DES (구식)
현재 표준은 AES (Advanced Encryption Standard). 128/192/256비트 키를 지원하며 전 세계 금융, 정부, 통신 시스템에서 사용됩니다.
실생활 활용 사례
💾
디스크·파일 암호화

🔒
HTTPS 세션 데이터
핸드셰이크 후 실제 웹 데이터는 AES로 빠르게 전송
📱
메시지 앱 E2E
Signal, WhatsApp 종단간 암호화의 실제 메시지 암호화 부분
🌐
VPN·WiFi 보안
WPA3, OpenVPN — 미리 공유된 키(PSK)로 무선 통신 보호

🐌
느린 속도
대칭 키 대비 수백~수천 배 느림. 대용량 데이터 직접 암호화에는 부적합
🔢
수학적 난제 기반
소인수분해(RSA), 이산로그(ECC)의 어려움에 의존. 양자 컴퓨터 시대 위협 대비 중
대표 알고리즘
RSA-2048/4096 ECC / ECDSA Diffie-Hellman Ed25519 (최신)
대칭 키 vs 공개 키 비교

키 수1개 (공유)2개 (공개 키 + 개인 키)
속도⚡ 매우 빠름🐌 느림 (100~1000배 차이)
키 배포사전 공유 필요 (취약점)공개 키는 자유롭게 배포 가능
디지털 서명불가능가능 (인증·부인방지)
주요 용도파일/디스크/세션 암호화키 교환, 인증서, 전자서명
대표 알고리즘AES, ChaCha20RSA, ECC, Diffie-Hellman
실전: HTTPS는 두 방식을 모두 씁니다 (하이브리드)
속도(대칭)와 안전한 키 배포(공개 키)의 장점을 모두 취하는 하이브리드 방식이 실제 인터넷에서 사용됩니다.

암호화 vs 해시 — 헷갈리면 안 되는 차이
항목암호화 (대칭·공개 키)해시
방향양방향 — 키가 있으면 복호화 가능단방향 — 원래 값으로 복원 불가
출력 길이입력에 따라 달라짐항상 고정 (SHA-256 = 64자)
키필요불필요
목적기밀성 (내용 숨기기)무결성 검증 · 비밀번호 저장
대표 알고리즘AES, RSASHA-256, SHA-3 (MD5·SHA-1은 구식)
실생활 활용 사례
🔑
비밀번호 저장
사이트는 비밀번호 원문이 아니라 해시만 저장. 유출돼도 원문을 알 수 없고, 로그인 때는 입력값의 해시를 대조
📥
파일 무결성 검증
다운로드 파일의 해시(체크섬)를 공식 값과 비교 — 한 비트라도 변조되면 지문이 달라져 즉시 탄로
⛓️
블록체인
각 블록이 이전 블록의 해시를 품고 있어, 과거 기록을 몰래 고치면 사슬 전체가 어긋남
✍️
디지털 서명의 재료
문서 전체 대신 문서의 해시에 서명 — 공개 키 탭의 서명 흐름과 이어지는 이야기
